QUICK START

A running server first.
The full stage next.

1 · Server and web portals

Docker Compose starts the API, administration, guest portal, SQLite state, and library access. Third-party providers and GPU alignment are optional.

git clone https://github.com/bmachuletz/NeonStageKaraoke.git
cd NeonStageKaraoke
cp .env.example .env
mkdir -p data
# set KARAOKE_LIBRARY_PATH and
# NEON_STAGE_PUBLIC_URL in .env
docker compose up -d --build server
curl http://127.0.0.1:5274/api/health

Open http://SERVER:5274/admin.html for administration and http://SERVER:5274/ for guests.

2 · Editor and Unity Stage

Build the native clients from the checkout, or use reviewed GitHub Release artifacts when available. Building the Stage requires a local Unity 6 installation.

./scripts/linux/build.sh
./scripts/linux/start-desktop.sh \
  http://127.0.0.1:5274

./scripts/linux/build-unity-stage-linux.sh
./scripts/linux/start-unity-stage.sh \
  http://127.0.0.1:5274

Complete song packages work without CUDA. Preparing or realigning new songs uses the separately managed EasyAligner stack.

DEPLOY IN MINUTES

One server.
Every screen.

Docker Compose server

Keep the media library and SQLite state on the host while the ASP.NET Core server runs in a reproducible container.

cp .env.example .env
# set host paths; integrations are optional
docker compose up -d --build server
curl http://127.0.0.1:5274/api/health

KARAOKE_LIBRARY_PATH and KARAOKE_DATA_PATH are configured in the ignored .env file. Spotify, Qobuz, USDB, CUDA alignment, and Online-Karaoke can be added later.

Linux editor AppImage

The self-contained x86_64 AppImage includes the editor runtime and LibVLC. Point it at any reachable Neon Stage server.

chmod +x NeonStage-LyricsEditor-x86_64.AppImage
KARAOKE_SERVER=http://SERVER:5274 \
  ./NeonStage-LyricsEditor-x86_64.AppImage

GPU alignment and request downloading remain separate worker workloads, so credentials, models, and karaoke media never enter application releases.
