Release builds

Neon Stage application releases never contain songs, audio, lyrics, cover art, generated stems, local databases, credentials, downloaded AI models, or alignment output. The CI media guard checks both source and packaged artifacts.

Run the editor AppImage

chmod +x NeonStage-LyricsEditor-x86_64.AppImage
KARAOKE_SERVER=http://SERVER:5274 \
  ./NeonStage-LyricsEditor-x86_64.AppImage

Deploy the server

cp .env.example .env
# configure host paths; Spotify and Online-Karaoke are optional
docker compose up -d --build server
curl http://127.0.0.1:5274/api/health

The media library and database remain bind-mounted host data. GPU alignment and downloader tooling run as separate worker workloads and are not included in the server image.

How releases are produced

  1. A reviewed version tag starts the GitHub release workflow.
  2. .NET tests and the source media guard must pass.
  3. The server is published without user data; the AppImage bundles only the editor runtime and required native libraries.
  4. LICENSE, NOTICE, and third-party notices are included.
  5. Packaged output is scanned again and SHA-256 checksums are generated.
  6. Tagged artifacts are attached to a GitHub Release.

One numbered local build

./scripts/release/build-release.sh --platform linux
./scripts/release/build-release.sh --platform linux,android

Product versions start at 0.1.0; a separate shared build number starts at 1 and identifies every platform artifact from the same run. After tests, packaging, license collection, media checks, and SHA-256 generation, the script asks whether it should create the matching prerelease and upload all files through the authenticated GitHub CLI.

Unity builds

Unity's current terms generally permit distributing the compiled runtime as part of a project when the applicable tier and terms are satisfied. The Unity Editor, Hub, license files, and build caches are never release artifacts. Unity Linux and Android artifacts require a protected licensed build environment. Optional macOS ARM64 and Windows x64 jobs use appropriately labelled self-hosted Unity runners. Android signing credentials, Unity licenses, and other platform secrets belong in encrypted repository secrets, never in source control.

Before installation

Verify the SHA-256 checksum, read the release notes, and configure your own server URL and empty local library. Media is added only by the operator after installation and remains outside the application directory.
